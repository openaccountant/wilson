## Headline

- **Only two of the three arms could be measured.** Arm **M17 (Qwen3-1.7B q4f16) does not load** in real WebGPU Chromium: ORT-web throws `Can't create a session. ERROR_CODE: 6, ERROR_MESSAGE: std::bad_alloc` while creating the ONNX session for `onnx-community/Qwen3-1.7B-ONNX` `q4f16` (a single 1,426,069,098-byte `model_q4f16.onnx`; no external-data shards). Reproduced three times: headless, headed, and headless with COOP/COEP (cross-origin isolated). Qwen3-0.6B q4f16 (569,789,750 bytes) loads fine on the same machine and harness. The other single-file 1.7B dtypes are all larger (q4 2.15 GB, bnb4 2.06 GB, int8 and uint8 1.74 GB). This also means the catalog entry `transformers:onnx-community/Qwen3-1.7B-ONNX` (`src/utils/model.ts:48`, "Qwen3 1.7B (WebGPU)") likely cannot load in the browser engine at all on this ORT build. **Escalated**, no M17 rows exist.
- Arms **T** (template, product default) and **M6** (model compose, Qwen3-0.6B q4f16) ran on all 196 rows on real WebGPU, and each is deterministic (second full run: 0 differences in gate, route, outcome, reason or answer text on all 196 rows).
- Bars 1, 4, 5 are computed below. **Bars 2 and 3 (precision, wrong-or-useless) need the blind grading and are not computed here.** The blinded file is `specs/eval/2026-10-03-round3-blind.jsonl` (46 lines: 27 T + 19 M6, shuffled, opaque ids). Do not open `2026-10-03-round3-key.json` until grading is done.

## How it was run

- Playwright full Chromium 153, headless; adapter vendor `apple`, architecture `metal-3`, `isFallbackAdapter: false`, `shader-f16: true`. The product's `createModelEngine` in a module Web Worker (transformers.js 4.3.0, ORT-web 1.31-dev) and the product's unmodified `runSubagent` loop (gate, keyword router, `fillArgs`, one tool step, compose, `classifyLocalOutput`, grounding). Tools run on the real mirror executors in a bun sidecar (bun:sqlite), one mirror per persona built from the synthetic persona seeds plus the generated v3 books (accounts, balance snapshots, loans). Persona seeds read from `<main checkout>/scripts/demos/personas` (synthetic, read-only); no `~/.openaccountant` data.
- Arm T: `--compose template` (the product default; zero compose generations, so the loaded model is idle; the 0.6B model is still loaded so the page and worker are identical across arms). Arm M6: `--compose model --model onnx-community/Qwen3-0.6B-ONNX --dtype q4f16`. Arm M17 attempted with `--model onnx-community/Qwen3-1.7B-ONNX --dtype q4f16` (the catalog dtype).
- Mutation flag: from the v3 row's own `mutation` field. Denylist flag ("row contains a word of the product's `MUTATION_VERB`") is computed by the harness from the product source.
- Load times (T / M6): first load 31.1 s / 29.6 s, warm worker respawn 2.2 s / 3.3 s.

## The blinded grading file

`specs/eval/2026-10-03-round3-blind.jsonl`, one line per locally answered (row, arm), shuffled. Fields: `id` (10 random hex chars), `q`, `expect` (the row's label), `answerNotes` (the v3 writer's, computed from the fixture tables), `tool`, `args`, `toolResult` (the full tool result), `answer`. **No arm label.** `specs/eval/2026-10-03-round3-key.json` maps `id` to `{arm, row, q, persona}`; keep it closed while grading.
Blinding limits a grader should know: the template arm's text has a fixed layout (period sentence, labeled figures, bullet lists), so some T answers are recognisable by style; the two arms never produce the same string for the same row (0 of 19 identical). Persona is not shown in the blinded line (the `q` plus `toolResult` carry what the grader needs; the key has the persona for resolving `answerNotes`).
Suggested rubric: unchanged from Round 2 (`2026-10-03-round2-results.md`): tool correct AND every figure and claim matches the tool result and the notes AND not useless (period and label stated, what-if applied, empty period called out).
